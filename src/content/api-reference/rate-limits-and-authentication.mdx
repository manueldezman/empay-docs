title: "Rate limits and API authentication"
description: "Understand EmPay request limits and JWT bearer authentication."
---

EmPay uses request limits to protect service capacity and JSON Web Token (JWT)
bearer authentication to identify users and enforce role permissions.

## Current rate limits

| Request type | Limit | Applied by |
| --- | --- | --- |
| General API requests | 100 requests per 15 minutes | IP address |
| Authentication requests | 15 requests per 15 minutes | IP address |

These values describe the EmPay application. The portfolio demonstration does
not enforce request limits.

## Handling rate limits

When a client exceeds an enforced limit, the API returns HTTP `429 Too Many
Requests`. Wait until the request window resets before retrying.

To reduce unnecessary traffic:

- Cache responses that change infrequently.
- Avoid repeatedly requesting identical data.
- Add retry delays after a `429` response.

## Using JWT authentication

Authentication to the EmPay API is performed using a JWT access token sent
through the standard HTTP `Authorization` header. Obtain the token by
[logging in](/api/default/api/auth/login/post), then include it with every
request to a protected endpoint:

```http
Authorization: Bearer <ACCESS_TOKEN>
```

The EmPay application issues access tokens that expire after seven days.

<Danger>
  Never publish or hard-code production JWT access tokens in public
  documentation or source code. Treat every token as a credential and transmit
  it only over HTTPS.
</Danger>

## Role permissions

EmPay checks the authenticated user's role after validating the token. An
authenticated user without the required role receives HTTP `403 Forbidden`.
See [roles and permissions](/concepts/roles-and-permissions) for the available
roles.
